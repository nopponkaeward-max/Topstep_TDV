# TopstepX Clicker: Renko Engulf (TradingView) → กดคีย์ลัด Buy/Sell บน TopstepX

บอทรันบน PC/Mac ของคุณ รับ Webhook จาก TradingView แล้ว **กดคีย์ลัด Buy/Sell Market ในหน้า TopstepX** ไม่ใช้ API ไม่ผ่านบริการตัวกลาง และ **ไม่ตรวจสถานะบัญชี** Indicator สั่งอะไร บอทกดตามนั้น

```
Indicator (Renko Engulf) → alert() JSON → Webhook (อุโมงค์ HTTPS) → bot/topstepx_bot.py → กดคีย์ลัดบน TopstepX
```

## ไฟล์
- `pine/renko_engulf_v6.pine` Indicator ที่เพิ่มโหมด `TopstepX Clicker` (ต้นฉบับ: `renko_engulf_v6.pine` ที่ใช้บนกราฟ Renko ของ TradingView)
- `bot/topstepx_bot.py` บอท, `bot/config.example.json` ตัวอย่างค่าตั้ง

## กติกาสัญญาณ
`Last Bull/Bear` ถูกบังคับปิดในโหมดนี้ (ใช้ `Immediate previous bar` เสมอ) และบังคับถือครั้งละ 1 ออเดอร์ ทำให้ 1 brick เกิดเหตุการณ์ได้อย่างมาก 1 อย่าง ไม่มีการกลับทิศใน brick เดียว

| เหตุการณ์ใน Indicator | บอทกด |
|---|---|
| เข้า long | กด Buy 1 ครั้ง |
| ออก long | กด **Close Position** (+ Cancel All) |
| เข้า short | กด Sell 1 ครั้ง |
| ออก short | กด **Close Position** (+ Cancel All) |

บอทกด **1 ครั้งต่อสัญญาณ** จำนวนสัญญาตั้งไว้ใน TopstepX แล้ว (ไม่มี qty ใน Indicator/บอท) เข้า-ออกใช้ขนาดเดียวกัน จึงปิดสถานะพอดี

ข้อความที่ Indicator ส่ง (`action` คือปุ่มที่ต้องกดจริงอยู่แล้ว):
```json
{"secret":"...","t":1759560000000,"action":"buy","event":"entry","id":"1759560000000-1234-e"}
```

## เลือกเงื่อนไขเข้า: **Entry mode** (กลุ่ม **Entry Strategy** ใน Indicator)
เลือกจาก dropdown:
- **`Engulf`** (ค่าเริ่มต้น) แบบเดิม: แท่งสีเดียวกันที่ครอบ High-Low ของแท่งก่อนหน้า
- **`Reversal`** แบบครอบ High-Low (ตารางด้านล่าง)
- **`NoWick Reversal`** แบบแท่งไม่มีไส้ (ด้านล่าง)
- **`W&M`** แบบรูปแบบแท่งเรียงกัน (ด้านล่าง) 
- **`Reverse Engulf`** แบบแดงคลุมเขียว (ด้านล่าง) 
- **`Double Bottom/Top (3-2-2-3)`** แบบ Double Bottom/Top (ด้านล่าง)  
- **`FollowTrend`** แบบตามเทรนด์ (ด้านล่าง) 
- **`RevEngulf02`** แบบแดงคลุมแดง (ด้านล่าง) และ `All + Pattern` = W&M + Reverse Engulf + Double + FollowTrend + RevEngulf02
- แบบที่มี `+` = ใช้หลายเงื่อนไขร่วมกัน (`Engulf + Reversal`, `Engulf + NoWick`, `Reversal + NoWick`, `All`) ข้อไหนเกิดก่อนก็เข้า

ช่อง **Reversal: จำนวนแท่งสีตรงข้ามติดกันขั้นต่ำ (N)** ใช้เมื่อเลือก Reversal (ค่าเริ่มต้น 4)

### เงื่อนไขแบบ NoWick Reversal (ใหม่)
| ทิศ | เงื่อนไข |
|---|---|
| **Buy** | มีแท่งแดงติดกันไม่ต่ำกว่า **N** แท่ง (ช่อง NoWick N ค่าเริ่มต้น 4) แล้วเกิดแท่งเขียว โดย **แท่งแดงที่ติดกับแท่งเขียว** และ **แท่งเขียวที่เกิด** ต้อง **ไม่มีไส้ (no wick)** ทั้งคู่ (แท่งอื่นๆ มีไส้ได้) |
| **Sell** | ตรงข้ามทุกอย่าง |

- no wick = High เท่ากับขอบบนของตัวแท่ง และ Low เท่ากับขอบล่างของตัวแท่ง (ยอมไส้ได้ตามช่อง `NoWick: ไส้ที่ยอมรับได้` ค่าเริ่มต้น 0 บวกครึ่ง tick)
- บนกราฟ Renko ของ TradingView แท่งขึ้นมีไส้ได้ที่ด้านล่าง ส่วนแท่งลงมีไส้ได้ที่ด้านบน (ด้านปลายแท่งไม่มีไส้)
- ไม่ต้องครอบ High-Low ของแท่งก่อนหน้า (ต่างจาก Reversal แบบแรก) ป้ายบนกราฟเป็น `Buy NoWick` / `Sell NoWick`

### เงื่อนไขแบบ RevEngulf02 (ใหม่)

อ่านจากแท่งเก่า → ใหม่:
1. แดงแท่งแรก **ไม่มีไส้ (no wick)** (ใช้เกณฑ์ NoWick เดียวกับโหมด NoWick)
2. แดงแท่งที่สอง High-Low **คลุมแท่งแรกทั้งหมด** (High ≥ High และ Low ≤ Low ของแท่งแรก ใช้ tolerance เดียวกับ Engulf)
3. **เขียว (เข้า Buy ที่แท่งนี้)** ที่ Low ต่ำกว่า Low ของแดงแท่งก่อนหน้า

- **Sell** = สลับสี: เขียวไม่มีไส้ → เขียวคลุมแท่งแรกทั้งหมด → **แดง (เข้า Sell)** ที่ High สูงกว่า High ของเขียวก่อนหน้า
- ป้ายเป็น `Buy RevEngulf02` / `Sell RevEngulf02`

### เงื่อนไขแบบ FollowTrend (ใหม่)

| ฝั่ง | รูปแบบ (เก่า → ใหม่) |
|---|---|
| **Sell** | แดง ≥ 3 → เขียว 2 → แดง 1 → เขียว 1 → **แดง 1 (เข้าที่แท่งนี้)** |
| **Buy** | เขียว ≥ 3 → แดง 2 → เขียว 1 → แดง 1 → **เขียว 1 (เข้าที่แท่งนี้)** |

- ช่วงแรกนับ 3 แท่งขึ้นไป ช่วงหลังนับเป๊ะ ป้ายเป็น `Buy FollowTrend` / `Sell FollowTrend`

### เงื่อนไขแบบ Double Bottom/Top (ใหม่)

| ฝั่ง | รูปแบบ (เก่า → ใหม่) |
|---|---|
| **Buy** | แดง ≥ 3 → เขียว 2 → แดง 2 → **เขียว 3 (เข้าที่แท่งเขียวที่ 3)** |
| **Sell** | เขียว ≥ 3 → แดง 2 → เขียว 2 → **แดง 3 (เข้าที่แท่งแดงที่ 3)** |

- ช่วงกลาง (2, 2, 3) นับเป๊ะ ช่วงแรกนับ 3 แท่งขึ้นไป ไม่เช็กว่าจุดต่ำ/สูงสองจุดเท่ากัน ป้ายเป็น `Buy Double` / `Sell Double`

### เงื่อนไขแบบ Reverse Engulf (ใหม่)

| ฝั่ง | รูปแบบ (เก่า → ใหม่) |
|---|---|
| **Buy** | เขียว → แดงที่ High-Low คลุมแท่งเขียวแรก → เขียว → **เขียว (เข้าที่แท่งนี้)** |
| **Sell** | แดง → เขียวที่ High-Low คลุมแท่งแดงแรก → แดง → **แดง (เข้าที่แท่งนี้)** |

- "คลุม" = High ≥ High และ Low ≤ Low ของแท่งแรก (ใช้ค่า tolerance เดียวกับ Engulf) ป้ายเป็น `Buy Reverse Engulf` / `Sell Reverse Engulf`

### เงื่อนไขแบบ W&M (ใหม่)

อ่านจากแท่งเก่า → ใหม่ แล้วเข้าที่แท่งสุดท้ายของรูปแบบ

| ฝั่ง | รูปแบบ |
|---|---|
| **Sell** | แดง ≥ **N** แท่ง → เขียว 1 → แดง 1 → เขียว 1 → **แดง 1 (เข้าที่แท่งนี้)** |
| **Buy** | สลับสี: เขียว ≥ **N** แท่ง → แดง 1 → เขียว 1 → แดง 1 → **เขียว 1 (เข้าที่แท่งนี้)** |

- N ตั้งได้ที่ช่อง `W&M: จำนวนแท่งสีเดียวกันติดกันขั้นต่ำ` (ค่าเริ่มต้น 3 = 3 แท่งขึ้นไป) ไม่เช็ค wick/engulf ป้ายบนกราฟเป็น `Buy W&M` / `Sell W&M`

### เงื่อนไขแบบ Reversal

| ทิศ | เงื่อนไข |
|---|---|
| **Buy** | มี **แท่งแดงติดกัน** ก่อนหน้าไม่ต่ำกว่า **N** แท่ง (ค่าเริ่มต้น N=4) แล้วเกิดแท่งเขียวที่ **High สูงกว่า และ Low ต่ำกว่า** แท่งแดงล่าสุด |
| **Sell** | ตรงข้าม: แท่งเขียวติดกัน >= N แล้วแท่งแดงที่ High สูงกว่า และ Low ต่ำกว่าแท่งเขียวล่าสุด |

- "แท่งล่าสุด" คือแท่งก่อนหน้าทันที (ซึ่งอยู่ในชุดแท่งสีเดียวกันที่ติดกัน) เทียบแบบ **มากกว่า/น้อยกว่าจริง** (ไม่ใช่เท่ากับ)
- **Exit / TP / SL ใช้ตามโหมดที่เลือกในกลุ่ม Exit Strategy** ป้ายบนกราฟเป็น `Buy Rev` / `Sell Rev` เมื่อเข้าด้วยเงื่อนไขนี้
- **ข้อสังเกต:** บนกราฟ Renko ของ TradingView แท่งกลับตัวมี Low = min(ราคาเปิด, ราคาต่ำสุดจริง) ส่วนแท่งแดงก่อนหน้ามี Low = ราคาปิดของมัน เงื่อนไข `Low ต่ำกว่า` จึงเกิดเมื่อราคาลงไปต่ำกว่าปิดของแท่งแดงล่าสุด (มีไส้) ก่อนกลับตัวขึ้นเท่านั้น (Sell ก็เช่นเดียวกัน) สัญญาณนี้จึงไม่ได้เกิดทุกครั้งที่กลับตัว
- ในโหมด `TopstepX Clicker` ถ้าเข้า Reversal ตรงกับแท่งที่ออกสถานะตรงข้ามพอดี (เช่น ออก short แล้วเข้า long) Indicator ส่ง **ข้อความเดียว** (`close_first`) บอทจะกด Close Position (+ Cancel All) ก่อนแล้วค่อยกด Buy (ถ้าเลือกวิธีออกแบบ `Opposite order` จะส่งเป็นสองข้อความที่เป็น `buy` ทั้งคู่ ซึ่งลำดับสลับได้) ส่วนการเข้า **ทิศเดิม** ใน brick เดียวกับที่เพิ่งออกจะไม่ทำ (กันคำสั่งสวนกัน)

## ตัวกรองช่วงเวลางดเทรด (กลุ่ม **Trading Hours (UTC+7)** ใน Indicator)
- ติ๊ก **เปิดตัวกรองช่วงเวลางดเทรด (UTC+7)** แล้วกำหนดได้สูงสุด 3 ช่วง รูปแบบ `HHMM-HHMM` เวลาไทย เช่น `0400-0600`, ข้ามเที่ยงคืนได้ เช่น `2300-0100` (เวลาเริ่มรวม / เวลาสิ้นสุดไม่รวม / `0000-0000` = ไม่ใช้ช่วงนั้น)
- ในช่วงงดเทรด **ไม่เปิดออเดอร์ใหม่** (ทุกเงื่อนไขเข้า) ส่วน **การออกจากออเดอร์ที่เปิดอยู่ยังทำงานตามปกติ** และไม่ได้สั่งปิดให้เองเมื่อเริ่มช่วงงดเทรด
- ใช้กับสถิติย้อนหลังด้วย (สัญญาณในช่วงงดเทรดไม่ถูกนับ) แท่งในช่วงงดเทรดแรเงาสีเทา (ปิดได้)
- เวลาที่ใช้ตัดสิน: ตอนทำงานจริง (realtime) = เวลาปัจจุบันตอน brick ปิด / ข้อมูลย้อนหลัง = เวลาของแท่ง (ประมาณ เพราะ brick Renko ไม่ผูกกับเวลาที่แน่นอน) ค่าเริ่มต้น: ปิดตัวกรอง ช่วงที่ 1 = `0400-0600` (ช่วงพักตลาด CME ประมาณ 04:00-05:00 หรือ 05:00-06:00 เวลาไทยตามฤดูกาล) ปรับให้ตรงกับที่ต้องการ
- ตัวกรองอยู่ใน Indicator ไม่ต้องแก้บอท (สัญญาณที่ถูกกรองไม่ถูกส่งไปบอทเลย)

## โหมดการออกจากออเดอร์ (กลุ่ม **Exit Strategy** ใน Indicator)
เลือกที่ dropdown **Exit mode** ได้ **อย่างเดียวเท่านั้น** ไม่ใช้ร่วมกัน (ช่องตั้งค่าของแต่ละโหมดอยู่ในกลุ่มเดียวกัน ขึ้นต้นด้วย `[โหมด 2]` / `[โหมด 3]`):

| # | Exit mode | ออกเมื่อ | ช่องที่เกี่ยวข้อง |
|---|---|---|---|
| 1 | **Opposite brick** (ค่าเริ่มต้น) | เจอ box สีตรงข้ามกับทิศที่ถือ (Buy เจอแดง / Sell เจอเขียว) | ไม่มี |
| 2 | **N same-color boxes** | มี box สีเดียวกับทิศที่ถือครบ N แท่ง (นับสะสม ไม่ต้องติดกัน) | N (ค่าเริ่มต้น 3), นับ box ที่เข้าเป็น box ที่ 1 |
| 3 | **TP / SL (price distance)** | ราคาไปถึง TP หรือ SL ที่ห่างจากราคาเข้าตามระยะที่ตั้ง | TP, SL (ค่าเริ่มต้น 5 / 5, 0 = ไม่ใช้ตัวนั้น) |

- แต่ละโหมดทำงานเดี่ยวๆ เช่น โหมด 2 **ไม่ออกเมื่อสีกลับ** และโหมด 3 ไม่ออกเมื่อสีกลับ หรือครบ N (ถ้าใช้โหมด 2 ไม่มี stop ระหว่างรอ ระวัง) ถ้าอยากได้ stop ให้ตั้ง SL ในแผงเทรดของ TopstepX หรือใช้โหมด 3
- คำสั่งออกที่ส่งไปบอทมีแบบเดียวคือ `close` **ไม่มีการส่ง Buy/Sell ตรงข้ามเพื่อออกอีกแล้ว** จึงไม่เสี่ยงเปิดสถานะกลับทิศ (ใช้ได้ทุกโหมดออก รวมถึงเมื่อ TopstepX ออกด้วย SL/TP ไปก่อน)
- ใช้ `Flatten All` แทน `Close Position` ได้ที่ `"exit_key": "flatten_all"` ใน `config.json` (ดูหัวข้อด้านล่าง)
- ในโหมด `TopstepX Clicker` จะ **ไม่เปิดออเดอร์ใหม่ใน brick เดียวกับที่เพิ่งออก** (กันบอทกดซื้อและขายพร้อมกัน) ต้องรอ brick ถัดไปที่ครอบคลุมตามเงื่อนไขเข้า
- ตาราง Stats คำนวณตามโหมดออกที่เลือก

### โหมด 3: TP / SL ตามระยะราคา
ระยะเป็น **หน่วยราคาของสินทรัพย์ (นับที่หลักหน่วย)** วัดจากราคาเข้า ตัวอย่างทอง เข้า Buy ที่ 4200.5:

| ตั้งค่า | Buy | Sell |
|---|---|---|
| TP = 5 | ออกที่ **4205.5** (ราคาขึ้น) | ออกที่ 4195.5 (ราคาลง) |
| SL = 5 | ออกที่ **4195.5** (ราคาลง) | ออกที่ 4205.5 (ราคาขึ้น) |

- **SL เป็นแบบคงที่** วัดจากราคาเข้า ไม่เลื่อนตามราคาที่วิ่งไปในทางกำไร ต่างจาก `Opposite brick` ที่เหมือน trailing
- ตรวจจาก **High/Low ของ brick ที่ปิดแล้ว (รวมไส้)** จึงจับกรณีที่ราคาแตะระดับ SL/TP ระหว่างที่ brick ก่อตัวได้ แม้ระยะไม่ลงตัวกับขนาด box
- ถ้าใน brick เดียวแตะทั้ง TP และ SL จะถือว่า **SL ก่อน** (เผื่อไว้แบบระวัง) เพราะดูไม่ออกว่าอะไรมาก่อน
- ผลสถิติ (จุดและ R) คิดที่ **ราคาระดับ SL/TP พอดี** ป้ายบนกราฟขึ้น `Close Buy TP` / `Close Sell SL`
- Indicator ส่งสัญญาณออก **หลังจาก brick นั้นปิด** (ช้ากว่าตอนราคาแตะจริง) ส่วนที่ออกทันทีคือ SL/TP ที่ตั้งในแผงเทรดของ TopstepX ให้ตั้งระยะเท่ากับใน Indicator สัญญาณที่ตามมาจะกด Close Position ซึ่งไม่เกิดอะไรถ้า flat อยู่แล้ว
- 1R ในตารางยังนับเป็น 2 box เหมือนเดิม (ไม่เกี่ยวกับระยะ SL ที่ตั้ง) เช่น box = 5 และ SL 5 จุด = -0.5R
- ถ้าตั้ง SL = 0 และ TP = 0 จะ **ไม่มีเงื่อนไขออกเลย** ระวัง
- ถ้ามีหลายออเดอร์ซ้อน (โหมดที่ไม่ใช่ TopstepX) ใช้ราคาเข้าของออเดอร์แรกเป็นตัวคำนวณ

## ข้อควรระวัง
- **เช็กกฎ Topstep เรื่องระบบอัตโนมัติก่อน** ผิดกฎอาจโดนปิดบัญชี
- **บอทไม่รู้สถานะจริง** ถ้าสัญญาณหลุด (เน็ตหลุด, เครื่องหลับ, บอทดับ) สถานะจะค้างหรือเกิน ต้องเฝ้าดูและปิดเอง
- **Indicator ไม่มี stop loss** ถือจนเจอ brick ตรงข้าม ตั้ง bracket ในแผงเทรด TopstepX หรือเฝ้าดู และระวัง Daily Loss Limit
- ราคาเข้าจริงไม่เท่าราคาปิด brick ในตาราง Stats (มี latency ของ Alert + การกด)
- เครื่องต้องเปิดอยู่ ไม่หลับ ไม่ล็อกจอ และหน้า TopstepX ต้องเป็นแท็บที่แสดงอยู่ **อยู่หน้าสุด ไม่มีหน้าต่างอื่นบังปุ่ม Buy/Sell** และอยู่ตำแหน่ง/ขนาด/zoom เดิมตอน calibrate (ขยับแล้วคลิกพลาด)
- **log ที่ขึ้นว่ากดคีย์แล้ว ไม่ได้ยืนยันว่าออเดอร์เข้า** ดูผลที่หน้า Positions ของ TopstepX เอง
- **เริ่มด้วย `dry_run: true` และบัญชี Practice เสมอ**

## ออกด้วย SL ใน TopstepX + Close Position (แนะนำ ลดความหน่วงฝั่งออก)
ตั้ง **Stop Loss 2 box** ในแผงเทรดของ TopstepX (เท่ากับระยะที่ Indicator ออกเมื่อเจอ brick สีตรงข้าม และเท่ากับ 1R) โบรกเกอร์จะตัดทันทีที่ราคาถึง โดยไม่ต้องรอ TradingView/บอท จากนั้นสัญญาณออกที่ตามมาทีหลังจะกด **Close Position**:
- ถ้า SL ปิดสถานะไปแล้ว (flat) → Close Position **ไม่เกิดอะไรขึ้น** ซ้ำได้โดยไม่เสียหาย (ต่างจากการกด Sell/Buy ตรงข้ามที่จะ **เปิดสถานะสวนทางใหม่** ถ้าสถานะถูกปิดไปก่อน)
- ถ้า SL ยังไม่ทำงาน (เช่น ราคาของ TradingView กับ TopstepX คลาดกัน) → Close Position ปิดให้ เป็นตัวสำรอง
- หลัง Close Position บอทกด **Cancel All** ต่อ เพื่อกัน SL/TP ที่ค้างเหลือเป็นคำสั่งกำพร้า (ปิดได้ที่ `cancel_after_close: false`) **Cancel All ยกเลิกคำสั่งรอทั้งหมด** ถ้าคุณมีคำสั่งรออื่นที่ตั้งเอง ให้ปิดตัวเลือกนี้
- ใน brick ที่ออกแล้วกลับทิศพอดี (เช่น Reversal) Indicator ส่ง **ข้อความเดียว** ที่มี `close_first` บอทจะกด Close Position → Cancel All → แล้วค่อยกด Buy/Sell ตามลำดับเสมอ (ไม่สลับลำดับ)
- **Close Position กับ Flatten All ต่างกัน:** Close Position ปิดสถานะของสัญลักษณ์ที่เทรด / Flatten All ปิดทุกสถานะในบัญชี (และมักยกเลิกคำสั่งรอด้วย) ตั้ง `"exit_key": "flatten_all"` ถ้าต้องการแบบ Flatten All (บอทกด Flatten All แล้วตามด้วย Cancel All) **ถ้ามีสถานะอื่นที่คุณถือเองในบัญชีเดียวกัน Flatten All จะปิดให้ด้วย** ค่าเริ่มต้นคือ `close`
- สิ่งที่ต้องทดสอบบน Practice ก่อน: Close Position ปิดเฉพาะสัญลักษณ์ที่เปิดอยู่ (ไม่ใช่ทั้งบัญชี), SL ที่ค้างถูกยกเลิกหรือไม่หลังปิด, และเวลาที่ SL ปิดสถานะไปแล้วแล้วกด Close Position ไม่มีผลข้างเคียง

## 3) อุโมงค์ Webhook (ngrok)
TradingView เรียกเข้าเครื่องคุณตรงๆ ไม่ได้ ต้องมี URL HTTPS สาธารณะที่ส่งต่อมาที่บอท (`127.0.0.1:8765`) เราใช้ **ngrok**

### ติดตั้งและตั้งค่าครั้งแรก (ทำครั้งเดียว)
1. สมัครบัญชีฟรีที่ <https://ngrok.com> แล้วเข้าหน้า Dashboard
2. ติดตั้ง ngrok
   - macOS: `brew install ngrok` (หรือโหลดจากหน้า Setup ของ ngrok)
   - Windows: โหลดจากหน้า Setup ของ ngrok หรือ `winget install ngrok.ngrok`
3. คัดลอกคำสั่ง authtoken จากหน้า Dashboard (หัวข้อ Your Authtoken) แล้วรันครั้งเดียว:
   ```bash
   ngrok config add-authtoken <โทเค็นของคุณ>
   ```
   ขึ้นข้อความ `Authtoken saved to configuration file` แปลว่าสำเร็จ
4. (แนะนำ) ดูโดเมนคงที่ฟรีของบัญชีที่หน้า Dashboard → Domains เช่น `ชื่อของคุณ.ngrok-free.dev` ใช้โดเมนนี้ใน Alert จะได้ไม่ต้องแก้ URL ทุกครั้งที่เปิดใหม่

### เปิดอุโมงค์ทุกครั้งที่จะเทรด
ใช้ **Terminal แยกอีกหน้าต่าง** จากหน้าต่างบอท (เปิดค้างทั้งสองหน้าต่างตลอดเวลาที่เทรด):

1. **หน้าต่างที่ 1: บอท**
   ```bash
   cd bot
   python3 topstepx_bot.py run
   ```
2. **หน้าต่างที่ 2: ngrok** (พอร์ตต้องตรงกับ `port` ใน `config.json` ค่าเริ่มต้น 8765)
   ```bash
   ngrok http 8765
   ```
   ถ้ามีโดเมนคงที่ของบัญชี: `ngrok http --url=https://ชื่อของคุณ.ngrok-free.dev 8765` (ดูรูปแบบคำสั่งล่าสุดในเอกสาร ngrok)
3. ดูบรรทัด **Forwarding** ในหน้าจอ ngrok เช่น
   ```
   Session Status   online
   Forwarding       https://ชื่อของคุณ.ngrok-free.dev -> http://localhost:8765
   ```
   URL ที่ขึ้นต้น `https://` คือ **Webhook URL** ที่ใส่ใน Alert ของ TradingView (ไม่ต้องใส่ `/` ท้ายหรือพอร์ต)
4. **เช็กว่าอุโมงค์ใช้ได้:** เปิด URL นั้นใน browser (ถ้าขึ้นหน้าเตือนของ ngrok ให้กด Visit Site) ต้องเห็นคำว่า `ok` และหน้าต่างบอทขึ้น `GET จาก ...`
5. เมื่อ TradingView ยิงมา จะเห็นแถว `POST /  200 OK` ในหน้าจอ ngrok และบอทขึ้น `รับ POST ...`
   - `403 Forbidden` = `secret` ไม่ตรงกัน (ใน Indicator กับ `bot/config.json`)
   - `202` = บอทรับแต่ไม่ทำ (สัญญาณซ้ำ, เก่าเกิน `max_age_seconds` หรือ action ไม่ถูกต้อง ดูเหตุผลใน log ของบอท)
   - หน้าเว็บ `http://127.0.0.1:4040` ของ ngrok แสดงรายละเอียดทุกคำขอ (มี `secret` อยู่ในข้อความ อย่าแชร์ภาพหน้านี้)

### เมื่อเลิกเทรด
กด `Ctrl+C` ที่หน้าต่าง ngrok และหน้าต่างบอท อุโมงค์ที่เปิดทิ้งไว้ คือช่องให้คนภายนอกยิงเข้าเครื่องคุณได้ (มีแค่ `secret` กันไว้)

### ข้อควรรู้
- **ต้องเปิดบอทและ ngrok พร้อมกันตลอดเวลาที่ Alert ทำงาน** ถ้า ngrok หรือบอทหยุด สัญญาณที่ TradingView ส่งมาจะหายไป (TradingView ไม่ส่งซ้ำ) ถ้ากำลังถือสถานะอยู่ สัญญาณออกจะไม่มา
- Alert ที่ยิงตอนอุโมงค์ยังไม่พร้อมจะส่งไม่ถึง ต้องเปิดอุโมงค์ให้เสร็จก่อนสร้าง/เริ่ม Alert
- เครื่องหลับหรือรีสตาร์ท อุโมงค์ก็หยุด ต้องเปิดใหม่ (ปิดโหมดหลับระหว่างเทรด)
- TradingView รับ Webhook เฉพาะ URL `https://` (พอร์ต 443) และต้องเปิด 2FA กับแผนที่รองรับ Webhook ไม่ใช่ปัญหาของ ngrok
- ใครรู้ URL + `secret` สั่งเปิดออเดอร์ในเครื่องคุณได้ เก็บ `secret` เป็นความลับ บอทกัน `secret` ผิด, สัญญาณซ้ำ (id) และสัญญาณเก่าเกิน `max_age_seconds` (ค่าเริ่มต้น 120 วินาที)
- ทางเลือกอื่น: **Cloudflare Tunnel** (ถ้ามีโดเมนของตัวเอง ใช้ named tunnel ได้ quick tunnel ที่ไม่มีโดเมน URL เปลี่ยนทุกครั้ง ไม่เหมาะ)

## 4) ตั้ง Indicator และ Alert
1. กราฟ **Renko** ของ TradingView (Chart type → Renko) ด้วยสัญลักษณ์ฟิวเจอร์สที่เทรดบน TopstepX
2. ใส่ `pine/renko_engulf_v6.pine` ตั้งค่า **Alert mode = `TopstepX Clicker`**, **Webhook secret** ให้ตรง `config.json` (ใช้กับแบบ A)
3. เลือกวิธีสร้าง Alert อย่างใดอย่างหนึ่ง:

### แบบ A: Any alert() function call (ส่งทุกสัญญาณใน Alert เดียว)
- Condition = Indicator นี้ → **Any alert() function call**, Notifications → **Webhook URL** ใส่ URL อุโมงค์ (ปล่อยช่อง Message ไว้ ข้อความมาจาก `alert()` มี `secret` อยู่ในข้อความ)
- ครบที่สุด: ส่งทั้งเข้า/ออก และกรณีออกแล้วกลับทิศใน brick เดียว (`close_first`) ลำดับไม่สลับ

### แบบ B: เลือกส่งทีละสัญญาณ (alertcondition) เช่น Buy อย่างเดียว / Sell อย่างเดียว / ไม่ใช้ Exit
เหมาะเมื่อโบรกเกอร์ออกเองด้วย SL/TP ใน TopstepX จึงไม่จำเป็นต้องส่ง Exit
- สร้าง Alert แยกตามที่ต้องการ: Condition = Indicator นี้ → เลือก **Renko Engulf Buy**, **Renko Engulf Sell**, **Exit Buy** (ปิด long) หรือ **Exit Sell** (ปิด short) ตัวใดตัวหนึ่งหรือหลายตัว ตั้ง Frequency เป็น **Once Per Bar**
- ช่อง **Message** ปล่อยตามค่าเริ่มต้น (เป็น JSON อยู่แล้ว) เช่น `{"action":"buy","event":"entry","id":"b-{{timenow}}","ts":"{{timenow}}"}` ข้อความนี้ **ไม่มี secret** (Pine ฝังค่าตั้งใน alertcondition ไม่ได้) ให้ใส่ secret ที่ **ท้าย Webhook URL** แทน:
  ```
  https://โดเมนของคุณ.ngrok-free.dev/?secret=รหัสของคุณ
  ```
  บอทรับ secret จาก URL ได้ (หรือจากข้อความ ถ้ามี) และใช้ `ts` ตรวจอายุสัญญาณเหมือนเดิม
- Exit ส่ง `close` (กด Close Position ซ้ำได้ ไม่เป็นอันตรายถ้า flat แล้ว)
- **ข้อควรระวังของแบบ B:**
  - ถ้าสร้างทั้ง Buy/Sell และ Exit เป็นหลาย Alert แล้ว brick เดียวเกิด "ออกแล้วกลับทิศ" (เปิด Reversal / NoWick) Alert แยกกันส่งถึงบอทลำดับไม่แน่นอน อาจเข้า Buy ก่อน Close แล้ว **ปิดสถานะที่เพิ่งเปิด** ถ้าใช้แบบ B ที่ไม่สร้าง Alert Exit เลย (ให้ TopstepX ออกด้วย SL/TP) ปัญหานี้ไม่เกิด
  - Indicator ยังนับสถานะภายในของตัวเอง และ **จะไม่ส่งสัญญาณเข้าใหม่ขณะที่คิดว่ายังถือออเดอร์อยู่** (One order at a time) ถ้าโบรกเกอร์ออกด้วย SL/TP ไปก่อน ให้ตั้ง **Exit mode = TP / SL (price distance)** ใน Indicator ให้ระยะเท่ากับที่ตั้งใน TopstepX เพื่อให้ Indicator เห็นว่าปิดไปแล้วและเข้าใหม่ได้
  - secret อยู่ใน URL ของ Alert (และขึ้นในหน้า ngrok `127.0.0.1:4040`) อย่าแชร์ภาพหน้าจอ
4. ตอนเทรด เปิด **บอท** (`python3 topstepx_bot.py run`) และ **ngrok** (`ngrok http 8765`) ค้างไว้ทั้งสองหน้าต่าง (ดูหัวข้อ 3)

## ทดสอบสายส่งด้วยปุ่มทดสอบใน Indicator
ไม่ต้องรอสัญญาณจริง (ใช้ได้ตอนตลาดฟิวเจอร์สปิด ให้เปิดบนสัญลักษณ์ที่ราคาขยับ เช่น BTCUSD):
1. ใน Indicator ตั้ง Alert mode = `TopstepX Clicker`, เปิด **ส่งสัญญาณทดสอบไปบอท**, เลือก **ทดสอบ action** (buy/sell)
2. สร้าง Alert ใหม่: Condition = Indicator นี้ → **Any alert() function call**, Webhook URL = URL อุโมงค์
3. เมื่อ Alert เริ่มทำงาน จะส่งสัญญาณทดสอบ **1 ครั้ง** บอทต้องขึ้น `รับ POST ...` แล้ว `entry buy` (หรือ `[DRY RUN] ...` ถ้า `dry_run: true`)
4. **ลบ Alert ทดสอบทิ้ง และปิดตัวเลือกทดสอบ** ก่อนสร้าง Alert จริง

## ความหน่วง (latency) ตั้งแต่สัญญาณถึงออเดอร์
เวลารวมมาจาก 3 ส่วน บอทวัดให้ในแต่ละสัญญาณ (ดูใน log):

| ส่วน | ที่มา | ควบคุมได้ไหม |
|---|---|---|
| ① TradingView สร้างสัญญาณ → ถึงบอท | TradingView ส่ง Webhook + ngrok + เน็ต | **ส่วนใหญ่ไม่ได้** (log: `สัญญาณมาถึงบอทหลังถูกสร้างใน TradingView X ms`) |
| ② บอทรับ → กดคีย์เสร็จ | โค้ดบอท + ดึงหน้าต่าง + ส่งคีย์ | **ได้** (log: `เวลาที่บอทใช้กด: X ms`) |
| ③ TopstepX รับคีย์ → ส่งออเดอร์ถึงโบรกเกอร์ | TopstepX/เครือข่าย | ไม่ได้ |

ลดส่วน ② (เวอร์ชันล่าสุดทำให้แล้ว):
- ไม่รอ 0.1 วินาทีต่อคำสั่งของ pyautogui อีกต่อไป (`PAUSE = 0`) และกดทั้งสามปุ่มพร้อมกันแล้วค้าง `key_hold_seconds` (ค่าเริ่มต้น 0.04 วินาที)
- **ไม่มีขั้นตอนตรวจ/ดึงหน้าต่าง TopstepX แล้ว** บอทกดคีย์ทันทีที่รับสัญญาณ (ไม่ใช้ `osascript` และไม่รอหลังดึงหน้าต่าง)
- อุ่นเครื่อง pyautogui ตอนเริ่มบอท ออเดอร์แรกจึงไม่ช้ากว่าปกติ

เพื่อให้เร็วที่สุด: ปล่อยหน้า TopstepX ไว้หน้าสุดและโฟกัสตลอด (อย่าสลับไปทำอย่างอื่นระหว่างเทรด) ใช้อินเทอร์เน็ตสาย LAN ปิดโปรแกรมที่กิน CPU และถ้าตัวเลข ① ใน log สูง (เช่น 1–2 วินาที) คอขวดอยู่ฝั่ง TradingView/เครือข่าย ซึ่งแก้ที่บอทไม่ได้

## ค่าใน `bot/config.json`
| ค่า | ความหมาย |
|---|---|
| `dry_run` | `true` = ไม่ทำจริง |
| `max_age_seconds` | ทิ้งสัญญาณที่เก่าเกินกี่วินาที (0 = ไม่เช็ก, ต้องให้นาฬิกาเครื่องตรงเวลา) |
| `key_hold_seconds` | เวลาค้างคีย์ก่อนปล่อย (ค่าเริ่มต้น 0.04 วินาที) ถ้า TopstepX จับคีย์ไม่ติดให้เพิ่มเป็น 0.08–0.1 |
| `hotkeys` | คีย์ `buy`, `sell`, `close`, `cancel_all` ตัวที่ไม่ใส่ใช้ค่าแนะนำตามระบบปฏิบัติการ |
| `exit_key` | คีย์ที่ใช้ปิดสถานะ: `close` (Close Position ค่าเริ่มต้น) หรือ `flatten_all` (Flatten All) |
| `cancel_after_close` | กด Cancel All หลัง Close Position (ค่าเริ่มต้น true) |
| `cancel_delay_seconds` | หน่วงระหว่างคีย์ Close → Cancel All → Buy/Sell (ค่าเริ่มต้น 0.1 วินาที) |

หยุดฉุกเฉิน: ลากเมาส์ไปมุมซ้ายบนของจอ หรือปิดบอท (Ctrl+C)
